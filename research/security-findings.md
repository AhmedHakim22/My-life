## 1. التهديدات الأمنية المكتشفة في مشاريع المصدر المفتوح وحلولها في نظامنا

| مجال التهديد | الخلل الشائع في مشاريع مفتوحة المصدر | مخاطره الواقعية | الحل الهندسي المطبق في معماريتنا |
| :--- | :--- | :--- | :--- |
| **تسريب بيانات اليوميات للـ AI الخارجي** | في بعض مشاريع Life OS (مثل فحص `edrisranjbar/lifeos` و `personal_planner`)، يتم إرسال نصوص الملاحظات واليوميات مباشرة لـ OpenAI/Anthropic APIs لتوليد ملخصات أو وسوم دون إذن صريح. | كشف أسرار المستخدم الشخصية ومشاعره وظروفه العائلية لخوادم شركات خارجية. | **حظر تام لنقل نصوص اليوميات والعبادات والأسرة لأي خدمة خارجية**. كل التحليلات والاقتراحات الصباحية تعتمد على محرك قطعي محلي (Local Deterministic Rules) يعمل 100% داخل المتصفح. أي ميزة ذكاء اصطناعي مستقبلية تكون باختيار صريح (Opt-in) مع تحذير واضح. |
| **عزل الحسابات والبيانات (Data Isolation / RLS)** | في تطبيقات تعتمد على قواعد بيانات مشتركة أو Firebase/Supabase دون قواعد أمان دقيقة، يمكن لأي مستخدم يمتلك مفتاح الـ API العام قراءة جداول المستخدمين الآخرين. | خرق خصوصية الأهداف والمهام وسجلات القراءة. | تطبيق **سياسات أمان مستوى الصفوف (Row Level Security - RLS)** في قاعدة بيانات Supabase PostgreSQL بشكل صارم: كل صف يحمل `user_id = auth.uid()`، ولا يمكن لأي استعلام قراءة أو تعديل سجل لا يملكه المستخدم، حتى عبر واجهة برمجة التطبيقات المباشرة. |
| **فقدان البيانات أثناء المزامنة غير المتصلة (Sync Conflicts)** | الكتابة في وضع عدم الاتصال (Offline) على الهاتف ثم فتح التابلت قد تؤدي لاستبدال التعديلات الأحدث ومسح الملاحظات بصمت (Silent Overwrite). | ضياع الملاحظات اليومية وموضع القراءة وتكرار الـ XP. | استخدام **المعرفات الفريدة المسبقة (UUIDs v4) وطوابع زمنية دقيقة (`updated_at` + Version Vector)** مع طابور مزامنة محلي (Sync Queue) في IndexedDB. عند حدوث تعارض، يتم دمج المهام المنفصلة وتنبيه المستخدم يدوياً في حال تضارب نصوص اليوميات بدلاً من المسح الصامت. |
| **تكرار نقاط الخبرة والـ XP (XP Duplication & Exploitation)** | إعادة إرسال طلب الشبكة (Network Retry) أو تعديل موضع القراءة عدة مرات قد يكرر احتساب نقاط الـ XP ويشوه التقدم العلمي. | تدمير المعنى النفسي للـ Gamification والوصول لرتبة أستاذ علوم بالغش البرمجي. | **دفتر أستاذ الـ XP غير القابل للتكرار (Idempotent XP Ledger)**: كل حدث يحمل `idempotency_key = sha256(event_type + entity_id + date)`؛ لا يمكن إدراج نفس المعاملة مرتين في قاعدة البيانات محلياً أو سحابياً. |
| **تسريب المفاتيح السرية (Secret Leakage)** | وضع مفاتيح `SUPABASE_SERVICE_ROLE_KEY` في شفرة الواجهة الأمامية للعميل. | تحكم كامل في قاعدة البيانات وتجاوز كل قواعد الأمان. | استخدام مفتاح العميل المحدود (`anon_key`) فقط في الواجهة الأمامية الخاضع بالكامل لقواعد الـ RLS، وحظر وجود أي مفاتيح سرية (Service Keys) في بيئة المتصفح. |

## 2. مصفوفة أمان البيانات والخصوصية حسب النوع (Data Classification Matrix)

| نوع البيانات | درجة الحساسية | التخزين المحلي (IndexedDB) | التخزين السحابي (Cloud Sync) | قواعد الحماية |
| :--- | :---: | :---: | :---: | :--- |
| **اليوميات والملاحظات الخاصة (Journal & Daily Notes)** | **فائقة الحساسية (Strictly Private)** | مخزنة محلياً، مع دعم التشفير بمفتاح مشتق من كلمة المرور (AES-GCM). | مشفرة ومعزولة بسياسة RLS الصارمة. | محظور إرسالها لأي جهة خارجية أو تضمينها في رسائل الخطأ أو الـ Logs. |
| **سجلات العبادات ومواقيت الصلاة** | **خاصة جداً (Private Personal)** | محلية داخل المتصفح. | معزولة للمستخدم فقط. | لا تُستخدم لأي تقييم ديني أو مقارنة مع مستخدمين آخرين. |
| **المقررات الجامعية ومحاضرات النانو** | **شخصية / أكاديمية** | متوفرة محلياً بالكامل. | متزامنة مع السحابة. | منظمة هرمياً ومحمية. |
| **الكتب والمهارات والكورسات** | **عامة / شخصية** | متوفرة محلياً. | متزامنة مع السحابة. | السجل الكنسي مشترك وتقدم المستخدم خاص به. |
| **سجل الـ XP والمستويات العلمية** | **حساسية منطقية (Integrity Critical)** | محلي محمي من التعديل اليدوي. | دفتر أستاذ مدقق (Immutable Ledger). | مفتاح عدم التكرار يمنع الازدواجية والتلاعب. |

- [x] تم التحقق: لا توجد مفاتيح سرية في كود الواجهة الأمامية.
- [x] تم التحقق: الخصوصية مضمونة 100% بعدم إرسال أي نصوص خاصة إلى LLMs خارجية.

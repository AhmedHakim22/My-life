# ADR-001: Adoption of Strategy D (Modular Composition) over Single-Repo Fork
**الحالة:** معتمد (Approved)  
**التاريخ:** 2026-10-21  
**المشاركون:** مهندس المعمارية، باحث المصادر المفتوحة، مالك المشروع

---

## السياق (Context)
بحثنا في المرحلة 2 عن أساس برمجي لبناء نظام تشغيل الحياة (Personal Life Coach OS). قارنا 4 خيارات رئيسية:
1. استنساخ مستودع مثل `lifeos-app/lifeos` أو `edrisranjbar/lifeos`.
2. توسيع مخطط مهام قائم مثل `personal_planner` أو `super-productivity`.
3. ربط خدمات منفصلة عبر الـ API (Memos + Booktracker + Vikunja).
4. بناء تطبيق معياري متكامل خفيف (Modular Composition) يقتبس أفضل المكونات المعيارية المجربة.

## القرار (Decision)
اعتمدنا **الاستراتيجية (D) — التكوين المعياري المتكامل**:
تأسيس تطبيق PWA خفيف بـ React 19 + TypeScript + Tailwind CSS، واقتباس محركات الصلاة (`adhan-js`)، والتكرار المتباعد (`ts-fsrs`)، ومخطط بيانات الكتب (`wars2k/booktracker`)، وبنية الـ XP والمزامنة من (`lifeos-app/lifeos`).

## النتائج والمبررات (Consequences & Rationale)
- **الإيجابيات:**
  1. صفر ديون تقنية: التخلص التام من كود سطح المكتب غير المطلوب لشركة تنظيف في `lifeos-app`، وكود PHP القديم في `edrisranjbar`.
  2. تحكم كامل 100% في تجربة الهاتف وإرجونوميا إبهام اليد والتدفق العربي الأصيل (RTL).
  3. استقرار التكلفة عند $0.00 شهرياً للأبد عبر باقات Cloudflare و Supabase المجانية.
  4. أمان قانوني كامل بحصر التراخيص في MIT و Apache 2.0.
- **السلبيات وتكلفتها:**
  - يتطلب بناء واجهة المستخدم وربط المحركات كتابة كود مخصص، لكنه كود نظيف ومحكوم وتحت سيطرتنا بالكامل.
